# 分析方法

本研究采用面向教程输出的分析方法，将技术文档转化为普通人可理解、可操作的教程内容。

## 分析方法一：步骤简化分析

### 目标
将官方文档的技术步骤转化为小白友好的操作指南。

### 分析要点
1. **步骤合并**: 识别哪些步骤可以合并或省略
2. **易错点标注**: 标注哪些地方容易出错，需要特别提醒
3. **预期引导**: 每个步骤完成后用户应该看到什么
4. **语言简化**: 用通俗语言替代技术术语

### 输出格式
- 编号清晰的步骤列表
- 每步只做一件事
- 包含「注意」「提示」标注
- 用"你会看到..."引导预期

## 分析方法二：前置知识分析

### 目标
确定读者需要提前准备什么，以及哪些概念需要解释。

### 分析要点
1. **必要准备**: 飞书账号、API Key 等前置条件
2. **概念解释**: 哪些概念需要简单解释（如"本地部署"、"API"）
3. **可跳过内容**: 哪些可以不讲（如服务器、Docker 等进阶内容）

### 输出格式
- 准备工作清单
- 简明概念解释（仅针对必须理解的概念）

## 分析方法三：场景价值分析

### 目标
展示 OpenClaw + 飞书能解决什么实际问题，激发读者兴趣。

### 分析要点
1. **使用场景**: 2-3 个具体的使用场景
2. **对比优势**: 与直接用 Claude/ChatGPT 网页版相比有什么优势
3. **适用人群**: 对个人和团队分别意味着什么

### 输出格式
- 场景描述（具体、可感知）
- 价值主张（简洁、有说服力）

## 分析方法四：深远意义提炼

### 目标
帮助读者理解这件事的意义，超越"工具使用"层面。

### 分析要点
1. **从工具到入口**: 飞书不再只是聊天工具，而是 AI 入口
2. **AI Agent 趋势**: 从"对话框"走向"自主执行"
3. **开源与自主可控**: AI 民主化的意义

### 输出格式
- 3-4 段简洁的意义阐述
- 保持克制，不过度渲染
- 用具体例子支撑观点

## 分析流程设计

### 第一阶段（并行执行）
- 安装步骤简化分析
- 飞书对接步骤简化分析
- 场景价值分析

### 第二阶段（汇聚整合）
- 整合为连贯的教程流程
- 提炼深远意义，确保与实操部分呼应

## 分析结果存储

所有分析结果以 Markdown 格式存储在 `data/02.analysis/` 目录下：

- `simplified-installation.md`: 简化后的安装步骤
- `simplified-feishu.md`: 简化后的飞书对接步骤
- `value-proposition.md`: 场景价值与深远意义分析
