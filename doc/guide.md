# AgentForge 新手入门教程

## 欢迎！

这是一份**手把手**的实战教程。我们将用一个完整的示例项目，带你从零开始体验 AgentForge 的完整流程。

预计用时：**30-45 分钟**（首次体验）

## 教程目标

完成本教程后，你将：
- ✅ 成功生成一个可运行的研究系统
- ✅ 执行完整的研究流程并得到报告
- ✅ 理解如何调整系统以适应自己的需求
- ✅ 掌握 AgentForge 的核心工作流程

## AgentForge 项目结构说明

在开始之前，让我们先了解 AgentForge 项目的目录结构和各个文件的作用。

### 核心文件（你需要使用的）

```
agent-forge/
├── user_input.md          # 🔴 用户输入模板 - 你需要填写的文件
├── generator.md           # 🟢 生成器提示词 - AI 读取它来生成研究系统

└── doc/                   # 📚 文档目录
    ├── 新手入门教程.md    # 📕 本文件 - 手把手新手教程
```

**文件说明**：

1. **user_input.md** - 你的起点

2. **generator.md** - 生成器大脑
   - 包含生成器的完整逻辑和架构原则

3. **README.md** - 快速开始指南
   - 英文版项目说明
   - 4 步快速上手流程
   - 适合快速了解项目

4. **doc/新手入门教程.md** - 本文件
   - 手把手的实战教程
   - 用完整示例带你走完全流程

## 第四步：运行研究系统（10-15 分钟）

现在是激动人心的时刻 - 让系统自动执行研究！

### 4.1 启动编排器

在 Claude Code 中，输入：

```text
请使用 ai-coding-tools-2025/agents/00.orchestrator.md 开始执行研究任务
```

### 4.2 理解执行机制（重要）

**执行方式**：
- ✅ **单一对话线程**：所有工作在你当前的 Claude Code 对话中完成
- ✅ **一个 Claude 实例**：不是多个 Claude 线程并行，而是一个 Claude 按编排器指示工作
- ✅ **智能体是指令**：智能体蓝图（.md 文件）是指令文档，不是独立进程

**并行执行**：
- 阶段间**总是串行**：数据收集 → 分析 → 报告（必须等上一阶段完成）
- 阶段内**可能并行**：取决于编排器如何设计
- 是否并行由 `user_input.md` 中的描述决定

**示例**：如果你在 `user_input.md` 写了"并行收集多个数据源"，生成器会创建并行执行的编排器。

### 4.3 观察执行过程

编排器会按以下顺序工作：

**阶段 1：数据收集**
- 读取 references 下的参考文件
- 启动数据收集智能体（可能并行启动多个 Task）
- 从多个数据源收集 AI 编程工具信息
- 保存到 data/01.materials/

你会看到类似的进度提示：
- 正在从 Product Hunt 收集数据...
- 正在从 GitHub Trending 收集数据...
- 已收集 12 个工具的信息
- 数据已保存到 data/01.materials/

**阶段 2：分析**
- 读取收集到的数据
- 按照分析方法进行分类、对比、趋势分析
- 保存到 data/02.analysis/

你会看到：
- 正在对工具进行分类...
- 已识别 3 个主要类别
- 正在进行特征对比分析...
- 分析结果已保存到 data/02.analysis/

**阶段 3：报告生成**
- 读取分析结果
- 按照报告模板生成最终报告
- 保存到 data/03.reports/

你会看到：
- 正在生成执行摘要...
- 正在撰写分类分析章节...
- 报告已生成：data/03.reports/final-report.md

## 第五步：调整和优化（重要！20-30 分钟）

**重要提示**：首次运行很可能不会得到完美结果！这是正常的。本章节教你如何通过与 AI 交互来逐步优化。

### 5.1 识别问题：首次运行后的自检清单

运行完成后，按以下清单检查结果：

**数据收集阶段检查** (`data/01.materials/`)：

- [ ] 数据量是否充足？（太少可能分析不够全面）
- [ ] 是否缺少重要的信息源？
- [ ] 数据质量如何？（是否有很多空白字段）
- [ ] 是否包含了你预期的关键对象？

**分析阶段检查** (`data/02.analysis/`)：

- [ ] 分析是否够深入？（还是只是简单罗列）
- [ ] 分析维度是否足够？
- [ ] 是否有实质性的洞察？
- [ ] 数据之间的关联是否被发现？

**报告阶段检查** (`data/03.reports/`)：

- [ ] 报告结构是否符合预期？
- [ ] 语言风格是否满意？
- [ ] 是否有逻辑性和说服力？
- [ ] 细节是否充分？

### 5.2 与 AI 交互式调整（最重要！）

**核心理念**：不要急于修改文件，先通过对话让 AI 帮你优化。

#### 策略一：直接对话式补充（最快速）

当你发现某个阶段的结果不够好，**直接在 Claude Code 中与 AI 对话**，让它基于现有结果进行改进。

**示例 1：数据不够充分**

❌ **不好的做法**：
```text
重新收集数据
```

✅ **好的做法**：
```text
我查看了 data/01.materials/ 目录，发现只收集了 8 个工具，
而且缺少一些我知道的重要工具，比如 Tabnine、Codeium、Amazon CodeWhisperer。

请你：
1. 补充收集这 3 个工具的信息
2. 再搜索一下是否还有其他主流 AI 编程工具被遗漏
3. 保存到 data/01.materials/ 目录

保持与现有文件相同的 JSON 格式。
```

**AI 会做什么**：
- 直接补充收集缺失的工具信息
- 不会重新收集已有的数据
- 保持格式一致

**实际对话示例**：

```text
👤 你：
我看了 data/01.materials/ 的数据，发现 GitHub Copilot 的信息太简单了，
只有基本介绍，缺少：
- 定价的具体档位
- 支持的编程语言列表
- 与竞品的具体对比

请你补充 GitHub Copilot 的这些信息，更新 data/01.materials/github-copilot.json
```

```text
🤖 AI：
我来补充 GitHub Copilot 的详细信息...
[搜索最新的定价和功能信息]
已更新 github-copilot.json，添加了：
- 个人版 $10/月，企业版 $19/月
- 支持 Python, JavaScript, TypeScript, Go, Ruby 等 20+ 语言
- 与 Cursor、Tabnine 的功能对比表
```

**示例 2：分析不够深入**

```text
👤 你：
我读了 data/02.analysis/classification.md，分类做得不错，
但分析太浅了，只是按功能分了 3 类，没有深入分析。

请基于现有分类，进行深度分析：
1. 每个类别的技术特点是什么？
2. 为什么这些工具会选择不同的技术路线？
3. 不同类别的优缺点对比
4. 市场趋势：哪个类别增长最快？为什么？

生成一个新的文件：data/02.analysis/deep-analysis.md
```

**实际效果**：AI 会基于已收集的数据进行深度分析，而不是重新开始。

**示例 3：报告语言需要优化**

```text
👤 你：
我看了 final-report.md，内容不错，但语言太平淡，缺乏吸引力。

请优化报告的语言：
1. 执行摘要部分：用更有冲击力的开场，突出最重要的发现
2. 趋势洞察部分：用更生动的语言描述趋势，增加一些类比
3. 整体语气：更专业但不失可读性，像 TechCrunch 的分析报告风格

保持原有结构和数据，只优化语言表达。
重新生成 data/03.reports/final-report.md
```

#### 策略二：分步迭代优化（更精确）

对于需要多次调整的情况，采用分步优化策略：

**步骤 1：先评估**

```text
👤 你：

从以下维度评价：

2. 分析深度（1-10分）
3. 逻辑性（1-10分）
4. 可读性（1-10分）

对每个维度，指出具体的优点和改进空间。
```

**步骤 2：根据评估结果针对性改进**

```text

请重点改进这一部分：
1. 补充对市场领导者（GitHub Copilot）的竞争优势分析
2. 分析新兴挑战者（Cursor）的差异化策略
3. 预测未来 12 个月的竞争格局变化

```

## 第六步：理解工作原理（5 分钟）

现在你已经成功运行了一个研究系统，让我们理解它是如何工作的。

### 6.1 智能体蓝图解析

打开 `ai-coding-tools-2025/agents/01.data_collector.md`，你会看到它用自然语言描述了：

- 智能体的角色
- 需要完成的任务
- 收集的具体要求
- 质量标准
- 输出格式

**这是声明式的**：
- 它描述"要做什么"（收集 AI 工具信息）
- 它描述"质量标准"（准确、完整、可靠）
- 但它不规定"具体怎么做"（AI 自己决定如何搜索、抓取、解析）

### 6.2 数据流转过程

数据在三个阶段之间流转：

```text
数据源（网站、API）
       ↓
[Data Collector] 收集并保存
       ↓
data/01.materials/*.json ← 人类可以检查
       ↓
[Analyzer] 读取并分析
       ↓
data/02.analysis/*.md ← 人类可以检查
       ↓
[Reporter] 读取并生成报告
       ↓
data/03.reports/final-report.md ← 最终成果
```

**关键特点**：
- 每个阶段的输出都保存到文件系统
- 人类可以在任何阶段检查、验证、修改数据
- 完全透明、可追溯

### 6.3 编排器的作用

编排器负责：
- 按正确顺序启动各个智能体
- 监控执行进度
- 处理异常情况

### 6.4 参考文件的作用

`references/` 目录下的文件是**领域知识**：

- `research-overview.md` - 所有智能体都会读它，了解研究背景
- `data-sources.md` - 数据收集智能体的参考
- `analysis-methods.md` - 分析智能体的参考
- `report-template.md` - 报告生成智能体的参考
- `style-guide.md` - 报告写作的风格指南

**关键理解**：
- 修改这些文件可以改变系统行为
- 不需要修改智能体蓝图代码
- 这就是"数据驱动"的威力

- ✅ 从小项目开始，逐步增加复杂度
- ✅ 限制数据范围，保证质量优先
- ✅ 提供具体的分析框架和示例
