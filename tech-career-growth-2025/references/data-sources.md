# 数据来源

本研究的数据来源包括以下几个类别：

## 1. 经典著作与能力模型

- 《The Staff Engineer's Path》
- 《Fundamentals of Software Architecture》
- 《Accelerate》（DORA 研究）
- 《Team Topologies》
- Google、Facebook 等大厂的技术职级体系与能力模型
- TOGAF、AWS 架构师认证等标准

**收集重点**：架构师能力定义、职级体系、评估标准

## 2. 决策与技术管理研究

- 《Thinking, Fast and Slow》
- 技术决策框架：ADR (Architecture Decision Records)、Trade-off Analysis
- 大厂技术博客中的决策案例：Netflix、Uber、Airbnb、Shopify 等

**收集重点**：决策框架、决策案例（成功与失败）、决策陷阱

## 3. 组织因素与工程文化

- Conway's Law 相关研究与案例
- 工程效能研究：Google、Microsoft 的开发者生产力研究
- 技术债务管理策略
- Google、Spotify、Netflix 等公司的工程文化文档
- Code Review、重构文化的最佳实践

**收集重点**：组织结构对代码质量的影响、工程文化建设案例、激励机制设计

## 4. 技术社区与专家观点

- Hacker News
- Reddit r/ExperiencedDevs
- 技术博客：Martin Fowler、Uncle Bob、Kent Beck 等
- 技术会议分享：QCon、GOTO、ArchSummit、极客时间

**收集重点**：资深技术人的经验分享、反直觉的洞察、真实案例

## 数据收集原则

1. **可信度优先**：优先收集大厂实践、权威研究、一手案例
2. **时效性**：重点关注 2020-2025 年的材料，必要时补充经典理论
3. **量化数据**：尽可能收集量化对比数据（如 DORA 报告中的指标）
4. **案例平衡**：既要收集成功案例，也要收集失败案例和反例
5. **多样性**：覆盖不同公司规模、行业、文化背景的案例
