## Research Project Basic Information

**Project Identifier**:
```
tech-career-growth-2025
```

**Research Topic and Core Questions**:
```
研究技术人的职业成长路径与核心竞争力建设。

核心问题:
1. 如何判断自己是否到了"架构师"阶段?
2. 技术人如何提升决策能力?
3. 10 年经验的人,真正值钱的是什么?
4. 为什么很多团队写不出好代码?(组织因素,而不是语言或个人能力)

研究意义:
帮助技术人理性认知职业发展阶段,识别能力短板,制定成长策略。帮助技术管理者理解如何培养团队、优化组织以提升工程能力。
```

**Preliminary Direction and Insights**:
```
初步假设:
- "架构师"不只是技术能力的跃迁,更是决策能力、影响力、系统思维的综合体现
- 决策能力的核心在于:信息收集、权衡取舍、风险评估、执行验证
- 10 年经验的价值不在于"写更快的代码",而在于"做更好的决策、避免更大的坑、带来更高的确定性"
- 团队写不出好代码的根本原因往往是组织因素:缺乏代码评审文化、缺乏重构时间、技术债务失控、架构腐化、激励机制不当等
- 不同职业阶段的核心竞争力不同:初期是"执行力",中期是"专业深度",后期是"判断力+影响力"

我希望通过这个研究验证这些假设,并提供能力模型、成长路径和实践建议。
```

**Analysis Methods**:
```
1. 能力模型构建与评估:

3. 因果链分析:
   - 组织因素 → 代码质量的因果关系

4. 案例研究:
   - 成功与失败案例分析,提取模式与反模式

5. 实践建议生成:
   - 能力提升方法、成长路径规划、避坑指南

1. 主题深度分析:对每个核心问题进行深度分析,提取模型、发现和数据

## Phase Three: Report Generation

**Report Format**:
```
Markdown 文档
```

**Report Structure**:
```
1. 执行摘要
   - 研究背景、主要发现、关键结论

2. 架构师的能力模型与判断标准
   - 什么是架构师?如何判断是否到了架构师阶段?
   - 核心能力模型:技术、决策、影响力、沟通、业务理解、领导力
   - 常见误区与优秀架构师的成长路径

3. 技术人如何提升决策能力
   - 决策能力的重要性
   - 技术决策的核心要素:信息收集、方案生成、权衡取舍、风险评估、执行验证
   - 结构化决策框架(ADR、Trade-off Analysis)
   - 常见决策陷阱与能力提升路径

4. 10 年经验的真正价值
   - 10 年 vs 3-5 年经验的核心差异
   - 从"写代码"到"做决策":更高的决策成功率、更强的风险预防、更快的问题诊断、更好的团队赋能
   - 如何最大化经验价值、警惕经验陷阱

5. 为什么很多团队写不出好代码
   - 代码质量的本质:组织问题而非技术问题
   - Conway 定律与组织结构的影响
   - 团队文化的影响:Code Review、重构、测试、质量意识
   - 流程、激励机制、时间压力、团队流动性的影响
   - 成功案例(Google、Spotify、Netflix)与改进建议

6. 职业成长的行动建议
   - 不同职业阶段的核心能力要求
   - 能力建设的具体方法
   - 职业路径选择(技术专家、架构师、技术管理)
   - 常见职业发展陷阱
   - 给技术管理者的建议

7. 附录
   - 能力评估清单、工具和框架、推荐资源、术语表、案例索引
```

**Writing Style**:
```
专业分析报告风格:
- 语言:简洁、客观、专业
- 结构:逻辑清晰,层次分明
- 数据:用数据和事实支撑观点
- 可视化:适当使用表格和分类展示
- 洞察:不仅描述"是什么",更要分析"为什么"和"意味着什么"
- 受众:面向技术人(工程师、架构师)和技术管理者
- 风格:除非必要,尽量不用 bullet points,用通顺的段落来组织。平实准确简练,不要起高调,不要乱打比方,不要啰嗦讲废话。原则上一件事只讲一遍,不要反复重复

参考风格:类似 Martin Fowler 的技术博客或《Accelerate》这类基于研究和数据的技术管理书籍
```

```
