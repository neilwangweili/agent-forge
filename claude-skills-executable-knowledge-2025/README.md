# Claude Skills 可执行知识范式研究项目

## 项目概述

本项目是一个基于 AgentForge 架构的研究型多智能体系统,旨在深入探讨 Claude Skills 所体现的"可执行知识"(Executable Knowledge)范式及其对软件本质的重新定义。

### 研究主题

**当知识变得可执行,软件的边界在哪里?**

传统软件范式中,知识与执行是分离的——代码负责执行,文档负责传递知识。但 Claude Skills 展示了一个全新范式:知识本身即是可执行的。用户通过安装 Skill (本质上是一份 Markdown 文档),即可获得处理特定信息的能力。这不是简单的"知识管理",而是知识的物化与能力的传递。

### 研究目标

通过深度分析 Claude Skills 的技术机制、设计理念和实践应用,揭示 AI 时代软件本质的深层变化,为软件工程师、架构师和技术管理者提供新的视角和洞察。

### 五个核心洞察

1. **知识的可执行性**:现代知识不再仅仅是"信息"或"说明",而是可以被下载、安装、执行的能力包
2. **协作的标准化**:Skills 安装在团队空间实现协作标准化,而非通过制度文档
3. **信息处理本质**:一切依赖信息的工作都是对知识的处理和再处理
4. **MAS/MAMAS 连接**:多智能体系统的协作节点本质上体现 Skills 理念
5. **范式转移**:从"面向对象编程"到"面向提示词编程"的根本性转变

## 系统架构

本研究系统采用 **声明式多智能体架构**,使用 **三阶段流水线模式**:

```
数据采集 → 分析 → 报告生成
```

### 核心设计理念

- **声明式而非指令式**:智能体蓝图用自然语言描述"要达成什么",运行时智能选择"如何做"
- **数据驱动**:领域知识外化为独立的参考文件
- **透明可追溯**:所有中间产物完全保留,数据流动清晰可见
- **质量内置**:质量标准嵌入智能体蓝图,AI 持续自检

## 如何使用

### 运行系统

在 Claude Code 中执行:

```
请使用 agents/00.orchestrator.md 来开始执行研究任务
```

Orchestrator 将自动:
1. 读取所有参考文件
2. 顺序启动三个阶段的智能体
3. 监控执行进度
4. 进行质量检查
5. 最后交付完整研究报告

### 查看结果

- **原始材料**: `data/01.materials/` - 采集的关于 Claude Skills、可执行知识、多智能体系统等的材料
- **分析结果**: `data/02.analysis/` - 五层分析的结果(概念提炼、范式对比、机制分析、因果链、实践验证)
- **最终报告**: `data/03.reports/` - 适合公众号发布的深度思考文章(约 4000 字)

### 工作流程

**阶段一:数据采集** (约 30-60 分钟)
- 收集五个维度的材料:Skills 机制、可执行知识理论、多智能体协作、软件范式演进、实践案例
- 输出到 `data/01.materials/`

**阶段二:分析** (约 60-90 分钟)
- 第一轮并行分析:概念提炼、范式对比、机制深度
- 第二轮汇聚分析:因果链分析、实践验证
- 输出到 `data/02.analysis/`

**阶段三:报告生成** (约 30-45 分钟)
- 整合分析结果
- 生成"引入-展开-升华"三段式文章
- 输出到 `data/03.reports/`

## 语言设置

- **智能体蓝图语言**: 中文
- **报告输出语言**: 中文

所有智能体蓝图和报告都使用中文编写。

## 研究特点

### 深度而非广度
- 不是 Claude Skills 的全面介绍
- 而是聚焦"可执行知识"这一核心理念的深度剖析

### 洞察而非教程
- 不是使用手册或功能介绍
- 而是透过 Skills 看软件本质变化的思考性文章

### 启发而非结论
- 不是给出确定性答案
- 而是提供新的视角和思考框架

### 平衡技术与哲学
- 有扎实的技术分析(机制、架构、实现)
- 也有深刻的哲学思考(本质、范式、未来)

## 目标读者

本研究的目标读者是:
- 对技术有基本了解的程序员
- 关注 AI 发展的架构师
- 思考未来软件工程方向的技术管理者
- 对软件本质感兴趣的知识工作者

他们不需要手把手的教程,而需要深度的洞察和启发。

## 质量标准

研究成功的标志:

1. ✅ 收集了全面深入的材料(五个维度都覆盖,既有技术也有哲学)
2. ✅ 完成了严谨的五层分析(概念、范式、机制、因果链、实践)
3. ✅ 生成了高质量的报告(4000 字,平衡深度与可读性)
4. ✅ 报告能够回答核心问题:"如果软件的本质是知识,那么 AI 时代的软件工程师到底在做什么?"
5. ✅ 为读者提供了新的视角和洞察

## 最终检验

文章完成后,应该能够:
- 让读者理解 Skills 机制的本质(可执行知识)
- 让读者认识到这种机制背后的范式转变
- 让读者开始思考这种转变对自己工作的影响
- 激发读者探索和实践的兴趣

## 调整和优化

如果需要调整研究方向或方法:
- **调整数据源**: 修改 `references/data-sources.md`
- **调整分析方法**: 修改 `references/analysis-methods.md`
- **调整报告结构**: 修改 `references/report-template.md` 或 `references/style-guide.md`
- **调整智能体行为**: 修改 `agents/` 目录下相应的蓝图文件
