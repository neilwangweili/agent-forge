# 写作风格指南

## 总体风格定位

**倡导性的专业技术写作**：这不是一篇中立的研究报告，而是一篇倡导性的技术文章。目标是通过充分的论证和实践指导，说服读者认同并采用 Scrum + XP + AI 方法论。

## 核心原则

### 1. 语言风格

- **简洁、准确、平实、简练、专业**
- 避免空洞的大话和比喻
- 不起高调，不啰嗦，不要乱打比方
- 原则上一件事只讲一遍
- 但要有说服力，清晰展示价值主张

### 2. 论证方式

- 用数据、案例和对比分析证明 Scrum + XP + AI 方法论的优势
- 所有对比和结论必须有数据、案例或引用来源支撑
- 避免空洞的理论，注重实践细节和可操作性

### 3. 结构组织

- 逻辑清晰，层次分明
- 使用恰当的标题和子标题
- **段落组织**：用通顺的段落组织内容，避免过度使用 bullet points
- 除非必要（如列举多个并列项），尽量不用 bullet points，用通顺的段落来组织

### 4. 数据支撑

- 所有对比和结论必须有数据、案例或引用来源支撑
- 数据要有明确来源和时效性
- 重点关注量化指标（如：交付周期缩短 X%、缺陷率降低 X%）

### 5. 实践导向

- 注重可操作性，提供具体的方法、步骤和示例
- 降低读者采纳的门槛
- 每章在介绍概念和优势后，都应该自然地引导读者理解"为什么应该使用这套方法"

### 6. 对比方式

- 在讲述 Scrum/XP + AI 优势时自然融入与传统方法的对比
- 突出改进效果
- 传统方法不单独成章，而是作为对比基准

### 7. 避免重复

- 同一个概念或数据只讲一次
- 不要反复强调
- 但要清晰展示价值主张

## 受众定位

- **目标读者**：软件工程师、技术经理、架构师
- **目标行动**：说服他们采用这套方法论

## 深度要求

- 既有概念解释，又有实践细节
- 既有理论支撑，又有案例验证
- 提供具体的代码示例（特别是小对象模式）和流程图

## 行动呼吁

在各章节适当位置加入对 Scrum + XP + AI 方法论的推荐和实施建议

## 文章基调

这不是一篇中立的研究报告，而是一篇倡导性的技术文章。目标是通过充分的论证和实践指导，说服读者认同并采用 Scrum + XP + AI 方法论。每一章在介绍概念和优势后，都应该自然地引导读者理解"为什么应该使用这套方法"。

## 参考风格

类似 Martin Fowler 推广重构和持续集成时的文章风格，或 Kent Beck 推广 XP 时的说服性写作：
- 平实而有说服力
- 用数据和案例说话
- 注重实践指导
- 清晰的价值主张

## 具体写作技巧

### 段落组织示例

**不推荐**（过度使用 bullet points）:
```
Scrum 的优势包括：
- 快速迭代
- 拥抱变化
- 持续交付
- 透明协作
```

**推荐**（用段落组织）:
```
Scrum 通过 2-4 周的快速迭代周期，相比传统瀑布模型数月的反馈周期，
显著缩短了从实现到验证的时间。这种短周期迭代使团队能够拥抱变化，
将需求变更的成本从瀑布模型的高成本降低到可接受的水平。同时，Scrum
的透明协作机制通过每日站会、Sprint Review 等仪式，确保团队成员和
利益相关者对项目进展有清晰的认知，提高了团队效能和客户满意度。
```

### 数据支撑示例

**不推荐**（没有数据支撑）:
```
TDD 可以提升代码质量。
```

**推荐**（有数据支撑）:
```
TDD 可以将缺陷率降低 40-80%（根据 IBM 和 Microsoft 的研究），
测试覆盖率提升到 90% 以上。
```

### 对比方式示例

**不推荐**（分离对比）:
```
第一章讲 Scrum
第二章讲瀑布模型的问题
```

**推荐**（自然融入对比）:
```
在第一章讲 Scrum 时，自然融入与瀑布模型的对比：
"Scrum 的 2-4 周迭代周期相比瀑布模型数月的反馈周期，显著缩短了..."
```

- [ ] 是否用通顺的段落组织内容，避免过度使用 bullet points？
- [ ] 是否在讲述 Scrum/XP + AI 优势时自然融入与传统方法的对比？
- [ ] 是否避免了同一个概念或数据的反复强调？
