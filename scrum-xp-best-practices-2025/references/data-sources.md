# 数据源

## 1. 敏捷宣言与 Scrum 官方资料

**描述**: Scrum 的权威资料，定义了 Scrum 的核心概念、角色、仪式和制品。

**来源**:
- Scrum Guide (官方指南)
- Agile Manifesto 及其原则
- Scrum.org、Scrum Alliance 等权威网站

**收集重点**:
- Scrum 的基本定义和核心概念
- 三个角色、五个仪式、三个制品的详细说明
- 与传统项目管理方法的对比

## 2. Extreme Programming 经典文献

**描述**: XP 的经典文献和权威资料，阐述 XP 的价值观和实践。

**来源**:
- Kent Beck 的《Extreme Programming Explained》
- Martin Fowler 关于 XP 实践的文章和博客

**收集重点**:
- XP 的五大价值观和 12 个核心实践

## 3. 传统软件开发方法论资料（用于对比）

**来源**:
- 瀑布模型（Waterfall Model）的定义、流程、优缺点
- 迭代模型、增量模型、螺旋模型等
- 传统方法论的失败案例和问题分析

**收集重点**:
- 瀑布模型的流程和问题（需求变更困难、反馈周期长、风险发现晚等）
- 量化数据：交付周期、变更成本、缺陷率等

## 收集目标

对每个方法论/实践/模式收集以下维度的信息：

- **基本信息**: 名称、提出者/来源、出现时间
- **核心问题**: 要解决的痛点/动机
- **思想**: 方法论代表的核心思想及渊源
- **实现概览**: 角色/流程/实践的具体操作方式、关键步骤
- **技术栈/常见实现**: 框架/工具/平台（如 Jira、JUnit、GitHub Actions 等）
- **适用场景与前置条件**: 团队规模、组织文化、技术成熟度要求
- **优势与劣势**: 效率/质量/灵活性/成本/认知负担（含量化对比数据）
- **成功/失误案例摘要与链接**
- **近年动态（2024-2025）**

## 详细程度要求

- 每个方法论/实践收集 500-1000 字的结构化信息
- 必须包含具体数据、案例或引用来源
- 避免空洞的理论，注重实践细节和可操作性
- 对比数据要有明确来源和时效性
